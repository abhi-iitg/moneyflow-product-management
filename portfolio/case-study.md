# MoneyFlow — Product Case Study

## 1. Problem

Young adults often have transaction visibility without financial clarity.

The product question:

> **How might we turn transaction data into a simple, repeatable financial decision-making habit?**

## 2. Product insight

The product should not try to become another "everything finance" dashboard.

The opportunity is narrower:

> **Make the weekly financial check-in useful enough that users return.**

## 3. Target user

Early-career professionals and students who want more control over everyday spending but dislike manual budgeting.

## 4. Product thesis

**See → Understand → Plan → Act → Learn**

## 5. MVP

- transaction import
- categorization
- cash-flow
- recurring expenses
- flexible budget
- savings goal
- weekly check-in
- privacy controls

## 6. Prioritization

RICE helped rank opportunities, while strategic fit and risk prevented the roadmap from becoming a purely numerical exercise.

The MVP deliberately avoids:
- investments
- lending
- autonomous transfers
- tax
- credit decisions

## 7. Key PM artifact

### PRD

The PRD translates the problem into:
- functional requirements
- user stories
- acceptance criteria
- analytics
- dependencies
- launch criteria

## 8. Metrics

North Star:
**Weekly Actionable Financial Check-ins**

Secondary:
- activation
- W4 retention
- action completion
- goal adoption

Guardrails:
- privacy incidents
- deletion failures
- insight correction

## 9. GTM

Beachhead:
students and early-career professionals.

Positioning:
> **Your weekly financial check-in.**

Acquisition:
- campus communities
- educational content
- referral
- product-led sharing

## 10. Experiment

First experiment:
**Privacy-first onboarding**

Hypothesis:
Clear data-handling communication will reduce uncertainty and improve import completion.

No experiment result is claimed in this case study.

## 11. What I would measure after launch

- Does the user reach value?
- Does the user take action?
- Does the user return?
- Does the user trust the product?
- Which action creates the strongest repeat behavior?

## 12. Biggest trade-off

### Why not bank integration first?

Because integration is expensive and creates trust/security complexity.

The first PM question is not:

> "Can we connect every bank?"

It is:

> "Will users repeatedly value the decision-support experience?"

Validate the wedge first; remove friction second.

## 13. What I learned

A strong FinTech product is not simply a finance dashboard.

The difficult PM work is deciding:
- which user to serve
- which problem to solve
- what not to build
- how to earn trust
- what success means
- how to learn from behavior

MoneyFlow is designed around those decisions.
